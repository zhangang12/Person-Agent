# 工作汇总：Agent 测试验证闭环 + 双模型（2026-07-28）

> 一句话：这一波把"Agent 干完活自己到底验没验、验得对不对"从靠自觉变成了**机器闭环**——它会自己写验证计划、开浏览器看、截图读图、判对错、改完再验，全程有机器盯着不许糊弄。
> 上一波（上下文治理/权限规则/提示词纪律）见 `docs/工作汇总-内网opencode弱模型整改.md`；设计依据见 `external/claude-code-测试手段借鉴.md`。

## 一、要解决的真问题

Agent（尤其内网弱模型）干完活只会嘴上说"完成了"：
- 改了代码不跑测试就交差；
- 让它验证，它"读一遍代码"就当验过——**读过 ≠ 跑过**；
- 前端任务 build 过了就算完，**页面根本没打开看过**；
- 报"测试通过"，其实根本没跑；
- 验证 FAIL 了没人管，修完也没人复验。

## 二、解法：一条机器盯着的验证闭环

```
编码分片干完活
   │
   ▼
证据闸（机判）：这一棒跑没跑过构建/测试/浏览器？没跑 → 标【未验证】
   │
   ▼
壳层自动派「验证棒」（新眼睛 + 多模态模型 + 只读沙箱）
   │  按 CC 验收员手册干活：build/test/lint 基线 → 分类型验证
   │  （后端 curl 看字段 / Bug 先复现 / 前端开浏览器点一遍+截图）
   │  → 至少搞一次破坏（重发/空值/超长）→ 逐步截图 → 读图判断
   ▼
VERDICT 机判：报告没写 VERDICT、或写 PASS 但没附命令证据 → 拒收回派（连 2 次转人工）
   │
   ├─ FAIL → 证据回灌实现者修复 → 同一根验证棒复验（最多 3 轮，到顶转人工）
   │
   └─ PASS → 壳层抽查重放：抽报告里一条命令真跑，对不上照样拒收
```

每一环都不靠模型自觉：要么机器判（闸），要么新眼睛验（验证棒），要么真跑给你看（抽查）。

## 四、关键实测发现（改变了方案）

1. **CC 根本不用提示词教"要写测试"**——它靠"测试命令固化进项目说明书 + 独立验收代理 + 调用方抽查"三层机制。我们照这个走：AGENTS.md 自动生成 + 验证棒 + 抽查重放。
2. **CC 的验收员提示词是全套反糊弄手册**："你的任务不是确认它能跑，是试图搞挂它""读过代码不算验证""全是 200 只算 happy path""没有 Command run 块的 PASS 是跳过不是通过"——全部翻写进了验证棒。
3. **双模型可行已实证**：同一会话不同消息可用不同模型（T8a），多模态模型真能读截图（T8b）；本机可选多模态有 5 个（Kimi K3/K2.7/HighSpeed/K3-256K/MiMo V2.5）。
4. **两个实测 bug 已修**：验证棒自己的只读沙箱触发了证据闸把自己标"未验证"（已对验证棒豁免）；复验时忘复位一次性标志导致第二次收官被吞（已修）。

## 五、怎么用（用户视角）

1. **选模型**：设置 → 双模型 → 主模型选干活的（如 MiniMax）、读图模型选会看图的（如 Kimi K3 / MiMo V2.5）。不配也能跑——带图消息回退老行为。
2. **AGENTS.md 不用管**：选项目就自动生成/刷新在项目根；想补充就手动改文件里「待确认」的地方（人工内容不会被覆盖）。
3. **验证过程可见**：分片做完没验证会被标【未验证】，壳层自动派验证棒；验证棒报告必须带 VERDICT 和命令证据，截图落在证据路径里可以点开看。
4. **糊弄的下场**：写 PASS 没跑 → 拒收回派；连续糊弄 → 转人工；FAIL → 修好会被同一根验证棒复查。
