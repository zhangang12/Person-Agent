# 测试验证闭环 · 实施计划（双模型架构 + 新功能冒烟闭环）

> **日期**：2026-07-27。**状态**：已确认开工（用户拍板三点：① 验证棒整卡跑多模态 ② 多模态从 serve 已配列表选 ③ 先列计划）。
> **本文取代** `docs/Agent测试能力加强-方案确认稿.md` 与 `docs/自主测试闭环-新功能冒烟方案.md` 的未实施部分（冒烟单由实现者写的旧设计已否决——**靶子画在需求侧，不画在实现侧**）。

## 0. 目标闭环（一张图）

```
规划/分析阶段      实现分片           验证棒(多模态整卡)              结果
────────────   ────────────   ────────────────────────   ──────────────
需求→验收点清单   按单干活        按清单逐条执行(browser/curl)
转换→对照表/旧系统  懵逼就问        逐步骤截图
(靶子)          不许瞎猜(箭)    读图判断(多模态读截图)
                                 ↓
                    修复 ◄── 回灌证据 ── VERDICT(机判+读图双路)
                    再验 ≤3 轮                │
                                 全过 → 冒烟单+证据归档(半回归资产)
```

**核心判据**：验收标准来自需求/分析侧（或转换的对照表/旧系统），验证棒是新眼睛，读图靠多模态整卡，失败回灌≤3 轮熔断。

## 1. 双模型架构（用户已拍板）

- **设置页两个模型位**：`modelMain`（干活）+ `modelVision`（读图），都从 serve 已配模型列表选（零新配置；`oc.listModels` 的 `image` 标志过滤多模态候选）。
- **路由**：普通会话走主模型；消息带图 → 该条消息自动切多模态（现有 hasImage 逻辑升级为显式设置）；**验证棒整卡用 modelVision 跑**（spawnWorkflow 的 shardModel 通道现成）。
- **历史净化**：多模态读完图后，历史里的图片 part 替换为"读图结论"文本——防主模型（非多模态）读图报错 + 省上下文。挂 context-guard 插件 `messages.transform` 做（读图 assistant 回答之后，把之前的 image part 换成占位文本）。
- **验证卡上下文管理（用户担心的爆上下文对策）**：① 图片读完即换结论，卡里最多一张"当前图"；② context-guard 历史清理/聚合预算对验证卡无差别生效（旧截图/旧工具结果只保最近 3 轮）；③ browser/curl 大输出走 read-spill 外溢；④ 冒烟证据归档落盘，上下文只留路径。

## 2. 阶段计划

### M0 · 探针 T8（半天，先行）
- forkcheck 加 T8：同一会话内主模型发一条文本、多模态模型发一条带图消息——验证 ① fork 支持消息级 model 切换 ② 多模态模型真能读图（让它描述截图内容）。
- 判定门：消息级切换不支持 → 降级"验证棒整卡多模态"独扛读图（仍可行）；多模态读不了图 → 读图环节降级 console+DOM 断言（闭环照跑）。
- 落点：`scripts/fork-capability-probe.mjs`。

### M1 · 双模型基座（1 天）
- settings 加 `modelMain/modelVision`（get/set-settings 白名单）；设置页两个下拉（候选 = listModels，多模态位按 `image:true` 过滤）。
- 消息级路由：`src/session.js` card-send——消息带图且有 modelVision → 该条用 modelVision 发（替换现有"临时找图模型"逻辑）。
- 验证棒整卡多模态：`window.js` spawnWorkflow 派【集成验证】时 `shardModel = modelVision || shardModel`。
- 历史净化：`plugin/bocomhermes-context-guard.js` 加规则——image part 在其后的 assistant 文本回答出现后，替换为 `[图片已读:结论见下文]`（同 ID 同决策）。
- 验证：session:test 补例（路由/净化）；ctxguard 补例。

### M2 · 验收点前置（1 天，本方案的"靶子"）
- **需求类**：主控规程/规划闸（`window.js` orchestratorSystemPrompt + workflowSystemPrompt）加一条——拆需求时必须产出【验收点清单】（人话："做完长什么样：页面有什么/点什么出什么/数据什么状态"），写进分片 goal；实现分片懵逼必须 question 问，不许瞎猜交付（进诚信四条）。
- **转换类（FLEX2React 等）**：验收标准 = 分析阶段的对照表/映射文档（有就引用其路径）；或"旧系统对照"（验证棒开旧页面操作取基准再对新页面同样操作逐项对比）——写进验证棒动作库。
- 验证：replay 用例（规程文本检查）+ 真实任务目检。

### M3 · 验证棒冒烟执行升级（1 天）
- `verifyGoalFor` 升级，验证棒工作流程（★ = 反向审查补强项）：
  ① **基线五步**（CC :43-47）：读 AGENTS.md/README/package.json 找命令 → build（挂=自动 FAIL）→ 测试套件（挂=自动 FAIL）→ lint/typecheck → 相关代码回归；**按风险定严度**（一次性脚本 vs 生产路径）★
  ② 读验收点清单/对照表，逐条执行（browser/curl）；前端链补 **子资源抽查**（HTML 200 但引用全挂的假象，CC :30）★
  ③ 每步 browser_screenshot → read 截图读图判断（布局/内容/白屏；无多模态降级 console+DOM 文本断言）
  ④ **对抗探针 ≥1**（并发/边界/幂等/孤儿，CC :63-72——全是 200 只算 happy path 不算验过）
  ⑤ **FAIL 三查**（CC :74-79）：Already handled（别处已防御）/ Intentional（文档注释说明有意）/ Not actionable（修了破坏外部契约 → 记 observation 不记 FAIL）★
  ⑥ 输出契约：VERDICT 字面量（**PARTIAL 仅限环境限制，能跑就必须判 PASS/FAIL**，CC :125 ★）+ Command run/Output observed（**copy-paste 原文不得转述**，CC :81-115 ★）
  ⑦ "测试套件是上下文不是证据"（CC :51——实现者也是 LLM，它的测试可能是循环论证）
- **验证棒工具面收窄**（CC :14-22,139-145 的只读沙箱思想）：验证棒 writeScope 限定为 `/tmp`（可写一次性复现脚本）+ read/browser/curl，**禁改项目文件**（复用 writeScope 硬闸，防验证棒"边验边改"自己当裁判又当运动员）★
- 落点：`src/window.js`（verifyGoalFor + 验证棒 writeScope 派发）+ `src/session.js`（writeScope 支持 /tmp 白名单）。
- 验证：replay 用例⑦（goal 含基线五步/读图/对抗探针/FAIL 三查/PARTIAL 限制；验证棒 writeScope 为 /tmp）。

### M4 · 循环熔断 + 归档（1 天）
- FAIL → 证据包（报错+截图路径+读图结论+对应验收点）按写归属回灌实现分片修 → **修完由【同一验证棒】继续验**（CC `prompts.ts:394` "resume the verifier with its findings plus your fix"——上下文重叠用 Continue，不开新棒）★；循环计数 ≤3，到顶标【验证未通过】转人工（复用 orchVerifyRetry 风格）。
- **调用方抽查重放**（CC :12 + `prompts.ts:394` 的 spot-check 落地）：验证棒 PASS 后，壳层（或主控）从其报告的 Command run 块里抽 1-2 条**只读命令**真跑一遍，输出对不上 → 按拒收处理（这是 CC 比我们先前机判多走的一步：不只看格式，还真重放）★
- 归档：`userData/smoke/<项目目录哈希>/<日期>-<功能>.md`（冒烟单+VERDICT+证据路径），供以后同类改动复用（半回归资产）。
- 验证：replay 用例⑧（FAIL→回灌→同棒再验→PASS；三连 FAIL→转人工；抽查重放不符→拒收）。

### M5 · 回归与文档（半天）
- 全量自测 + replay 全套；台账登记（验证棒多模态/验收点前置进观测期）；AGENTS.md 补"双模型与验证闭环"一节；`docs/工作汇总` 增补本波。

## 3. 风险与降级

| 风险 | 降级 |
|---|---|
| fork 不支持消息级 model 切换（M0 探针判） | 验证棒整卡多模态独扛读图；消息级带图退回"临时找图模型"现状 |
| 内网多模态模型读图弱/无 | 读图环节降级 console+DOM 文本断言（browser_get_text 对预期文案），闭环照跑 |
| 验收点清单弱模型写不好（规划阶段也懵逼） | 清单进规划闸由人过目（批准闸本来就有）；转换类优先用对照表/旧系统（客观基准） |
| 读图截图撑爆验证卡上下文 | §1 历史净化四件套；图片读完即换结论，旧图不留在上下文 |

## 4. 反向审查：本计划 vs Claude Code 设计（2026-07-27 核）

> 方法：拿 M0-M5 逐条对 `verificationAgent.ts` / `prompts.ts` / `init.ts` / `init-verifiers.ts` / `claudeInChrome/prompt.ts`。结论：**骨架一致，9 处已按 CC 补强（M3/M4 内★号），3 处有意偏离（附理由），2 处 BH 自研补充**。

### 5.1 已补强（原计划的漏洞）

| # | 漏了什么 | CC 出处 | 补强位置 |
|---|---|---|---|
| 1 | 验证棒只有冒烟执行，缺**基线五步**（build/test/lint 挂=自动 FAIL + 相关回归 + 按风险定严度） | `verificationAgent.ts:43-49` | M3① |
| 2 | 前端链缺**子资源抽查**（HTML 200 但引用全挂的假象） | `verificationAgent.ts:30` | M3② |
| 3 | 缺 **FAIL 三查**（Already handled/Intentional/Not actionable→observation）——没有它误报会把实现者淹了 | `verificationAgent.ts:74-79` | M3⑤ |
| 4 | PARTIAL 没限制（CC：仅限环境限制，能跑就必须判 PASS/FAIL） | `verificationAgent.ts:125` | M3⑥ |
| 5 | 证据"copy-paste 不得转述"没写 | `verificationAgent.ts:81-115` | M3⑥ |
| 6 | **验证棒工具面没收窄**——CC 的 verifier 是只读沙箱（禁 Edit/Write 项目文件，只许 /tmp 脚本），防"边验边改"；原计划验证棒是完整工具面 | `verificationAgent.ts:14-22,139-145` | M3 工具面（writeScope 复用） |
| 7 | **调用方抽查重放**（PASS 后重跑报告里 1-2 条命令核对输出）——CC 的机判不只看格式还真重放，原计划只有格式机判 | `verificationAgent.ts:12`、`prompts.ts:394` | M4 |
| 8 | 修复循环没说明用哪根棒——CC 是"resume the verifier with findings"（上下文重叠用 Continue，不开新棒） | `prompts.ts:394`、coordinator Continue/Spawn | M4 |
| 9 | AGENTS.md 缺 dev server **三要素**（怎么起/URL/什么文本算就绪），验证棒起服务会抢跑 | `init-verifiers.ts:47-50` | `src/agent-md.js` 检测器补 ready 文本探测与 wait_for 剧本（随 M1 顺带） |

### 5.2 有意偏离（CC 没有或不适合 BH）

| # | 偏离 | 理由 |
|---|---|---|
| 1 | **冒烟单/验收点前置**：CC 的验证代理自己看 diff 定检查项（它模型强）；BH 弱模型"自己想该验啥"不靠谱，改由规划/分析侧产清单，验证棒照单执行 | 弱模型约束，用户拍板 |
| 2 | **双模型架构**：CC 单一多模态模型；BH 主模型可能无多模态，拆主模型+读图模型，配图→文历史净化 | 内网模型现实，用户拍板 |
| 3 | **冒烟单归档半回归**：CC 靠仓库测试代码沉淀；BH 大量项目无测试框架 | 内网项目现实 |

### 5.3 BH 自研补充（CC 无对应物）

- 证据闸/VERDICT 机判的**壳层硬机制**（CC 的 "report gets rejected" 只是提示词威慑，BH 做成真拒收+回派，db6a880）
- 浏览器自验技能（BH 内嵌浏览器 MCP 形态）与 browser 动作轨入证据体系
- AGENTS.md 自动生成+自动插入（CC 的 /init 是手动命令，BH 免手点）

### 5.4 对齐确认（不用动的）

角色翻转/借口清单/对抗四件套/PARTIAL 语义/VERDICT 字面协议/新眼睛原则/诚信四条/测试套件不可全信——均已在前波（V1-V3、提示词借鉴）落地且与 CC 语义一致。
