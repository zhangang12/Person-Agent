# 编排引擎(src/orch/)· 接口契约

> 这是 P1「纯逻辑」阶段的**唯一事实源**。实现与测试都照它写,不许各自发挥。
> 设计背景与取舍见 `docs/编排重构-设计.md`;本文件只定接口。

## 0. 为什么要有这一层

现状:编排的控制流没有被代码持有 —— 它被序列化成中文、用 `card-inject` 塞进一张 LLM 卡当成对话回合,
再指望模型把壳层已经知道的账(派了几片、齐没齐、第几轮、缺哪些签名、跑没跑测试)重记一遍。
59 道兜底闸里 42 道不是在纠正「模型判断错」,而是在补「这件事本来就该由代码做」。

本层的分工铁律:

> **控制流归代码,判断归模型。代码永远不替模型做决定,模型永远不替代码记账。**

具体到两条可执行的判据:
- 凡是**数得出来/查得到**的(几个节点、谁完了、文件在不在、退出码多少、契约签名有没有)→ 代码,模型不许被问;
- 凡是**要权衡**的(怎么拆才划算、这片失败该怎么拆更小、够不够收口、结论可不可信)→ 模型,代码不许替它兜底成默认值。

## 1. 模块边界(硬约束,`scripts/orch-boundary-check.mjs` 会 grep 检查)

| 文件 | 允许 require | 禁止出现 |
|---|---|---|
| `src/orch/ledger.js` | 无 | 一切 |
| `src/orch/schema.js` | 无 | 一切 |
| `src/orch/nodes.js` | 无(fs/exec 由 probe 注入) | `require('fs')` `require('child_process')` `electron` |
| `src/orch/render.js` | `./ledger` | `electron` `fs` `net` |
| `src/orch/run.js` | `./nodes` `./ledger` | `electron` `fs` `net` `Date.now(` `Math.random(` |

`run.js` 的三条禁令是**可重放性**的前提:时间一律由事件带进来(`ev.at`),id 一律由外部注入的 `mkId` 生成。
只要 `applyEvent` 是纯函数,replay 就能拿同一串事件重放出同一个 run。

## 3. `src/orch/run.js`

```js
module.exports = {
  createRun(spec, ctx),        // spec:{goal,dir,backendDir,model,alias,concurrency,budget?} ctx:{at, mkId}
                               //   → Run(phase='planning')。不产生 effects,调用方紧接着 applyEvent(RUN_START)
  applyEvent(run, ev, ctx),    // → { run, effects }  ★纯函数:不读时钟/fs/S;新 run 是新对象(不原地改)
  readyNodes(run),             // → Node[]  deps 全 verified/skipped 的 pending 节点
  invariants(run),             // → string[] 违反的不变式描述(空 = 健康);只写日志不改状态
  projectSnapshot(run),        // → 给渲染端的只读投影(见 §7)
}
```

### 3.1 事件全集(`ev.type`)

每个事件都带 `at`(毫秒);`ctx.mkId(prefix)` 用于生成 nodeId/decisionId。

| type | 载荷 | 语义 |
|---|---|---|
| `RUN_START` | — | 起 plan 决策 |
| `DECIDED` | `{ decisionId, point, ok, data, invalid }` | 决策回来了(合法/不合法都走它) |
| `USER_APPROVE` | `{ edits? }` | 批准方案 |
| `USER_REJECT` | `{ note }` | 打回重规划 |
| `USER_NOTE` | `{ text }` | 用户插话 |
| `USER_ABORT` | — | 中止整个 run |
| `USER_RETRY` | `{ nodeId }` | 对 failed 节点手动再来一次(maxAttempts++) |
| `USER_RESUME` | — | suspended → executing |
| `TICK` | — | 推进:派发/判空/触发 frontier 决策 |
| `NODE_DISPATCHED` | `{ nodeId, cardId, wcId, sid }` | 卡真开出来了 |
| `WORKER_TURN_START` | `{ nodeId }` | |
| `WORKER_TURN_END` | `{ nodeId, final, files, rounds, aborted }` | |
| `WORKER_TURN_ERROR` | `{ nodeId }` | 错误轮 ≠ 结束 |
| `WORKER_CARD_GONE` | `{ nodeId }` | 卡被关/销毁 |
| `TIMER` | `{ nodeId, key:'silent'|'stall' }` | |
| `EXIT_RESULT` | `{ nodeId, pass, report, verdict, cmdExit, contractMiss, unverified }` | evalExit 跑完(需要 fs/exec,所以在 index.js 里跑,结果回灌) |
| `BUDGET_EXCEEDED` | `{ what }` | |
| `PANEL_CARD_GONE` | — | 面板卡关了 → cancelled |

### 3.2 Effect 全集(返回给 `index.js` 执行,执行结果作为**新事件**回灌)

```js
{ type:'dispatch',   nodeId }
{ type:'cancelNode', nodeId, why }
{ type:'decide',     decisionId, point, event, nodeId }
{ type:'evalExit',   nodeId }
{ type:'armTimer',   key, nodeId, kind:'silent'|'stall', ms }
{ type:'clearTimer', key }
{ type:'persist' }
{ type:'ui' }
{ type:'notify',     level:'info'|'warn', text }
{ type:'archive' }
```

**计时器键恒为 `runId + ':' + nodeId + ':' + kind`** —— 不用 wcId(钉出/重挂后 wcId 会变,旧计时器成孤儿)。

**Run.phase**

| `planning` | `RUN_START` | `planning` | `decide(plan)` `persist` `ui` |

| `planning` | `DECIDED(plan, invalid)` ×2 | `awaiting-user` | `ui` —— 三选一,**绝不静默兜底成默认拆法** |
| `awaiting-approval` | `USER_APPROVE` | `executing` | 应用 edits → `TICK` |
| `awaiting-approval` | `USER_REJECT` | `planning` | 记 note;`decide(replan, 'user-reject')` |
| `executing` | `TICK` & 有 ready & 有容量 | `executing` | `dispatch × k` `persist` `ui` |
| `executing` | `EXIT_RESULT` → 节点终态 | `executing` | `decide(replan,'node-settled'\|'node-failed')` ★**每节点必调 = 反死板核心** |
| `executing` | `TICK` & 无 ready & 无 running & 无 pendingDecision | `executing` | `decide(replan,'frontier')` ★**代码不替它宣布收口** |

| `executing` | `DECIDED(replan,{done:true,final})` & 无 running | `done` | `cancelNode(全部)` `archive` `notify` |
| `executing` | `DECIDED(replan,{askUser})` | `awaiting-user` | `ui` |
| `executing` | `USER_NOTE` | `executing` | 无 pendingDecision → `decide(replan,'user-note')`;否则挂起,**下次 render 必带,永不丢** |
| `executing` | `BUDGET_EXCEEDED` / `invalidStreak>=3` | `awaiting-user` | `cancelNode(running)` `ui` ★**不许自动收口** |
| `awaiting-user` | `USER_NOTE`/`USER_APPROVE` | `executing` | `decide(replan,'user-answer')` |

**Node.state**

| 当前 | 事件 | → | 说明 |
|---|---|---|---|
| `pending` | `TICK` & deps 满足 & 有容量 | `queued` → `running` | `dispatch` + `armTimer(silent,45s)` + `armTimer(stall,15min)` |
| `pending` | `TICK` & deps 满足 & 无容量 | `queued` | **不进全局 `S.wfQueue`**,停在 run 内 |
| `pending` | `TICK` & deps 里有 `failed` | `skipped` | `droppedReason='上游失败'` |
| `running` | `WORKER_TURN_START` | `running` | `clearTimer(silent)` |
| `running` | `WORKER_TURN_END` | `running` | 记 result;`armTimer(silent,45s)`;**不看 todos** |
| `running` | `WORKER_TURN_ERROR` | `running` | `armTimer(silent,45s)` |
| `running` | `TIMER(silent)` | `settled` | `evalExit` |
| `running` | `TIMER(stall)` / `WORKER_CARD_GONE` | `settled` | `cancelNode`;`reason='stalled'\|'card-gone'`;`evalExit` |
| `settled` | `EXIT_RESULT(pass)` | `verified` | `cancelNode(自己)`;facts 入账;`decide(replan)` |
| `settled` | `EXIT_RESULT(!pass)` & `attempt<max` | `rejected` → `pending` | `attempt++`;brief 追加拒因 |
| `settled` | `EXIT_RESULT(!pass)` & `attempt>=max` | `failed` | gaps 入账;`decide(replan,'node-failed')` |
| `verified` | `WORKER_TURN_START` | `running` | ★**合法转移**(交棒/复活),不是异常,不需要任何一次性标志 |
| `failed` | `USER_RETRY` | `pending` | `maxAttempts++` |
| `pending`/`queued` | `DECIDED(replan,{dropNodes})` | `skipped` | ★只有**未 running** 的能被砍 |
| 终态 | 重复事件 | 不变 | **幂等吸收** —— 这是「旧报文重跑机判」结构上不可达的根据 |

### 3.3b 退出闸不过:先补做,补不动才重做(2026-07-31 评审修正)

原稿一律 `cardId/wcId/sid = null` 开新卡重来,理由写的是"新眼睛防锚定"。评审指出这是设计缺陷:
**退出闸不过 ≠ 这片白干了**。六类闸里只有 `noEmpty`(零产出)意味着这张卡根本没干活;
其余五类(`artifacts` 缺产出 / `contract` 缺签名 / `evidence` 没跑构建测试 / `verdict` 没出结论 / `cmd` 退出码非零)
都是**活干了但差一截**。差一截就该在**原卡原会话**里把差的那截补上 —— 它的上下文还在,知道自己刚写了什么,
补一项通常一个回合就完;而重做要新开卡从零重读,既贵,又可能把上一轮已经做对的部分改成别的样子。
最荒唐的是 `evidence`:代码都写完了,只是没跑 `npm test`,却要新开一张卡把整片重做一遍。

**判据(全满足才补做):**

| 条件 | 为什么 |
|---|---|
| 失败项里不含 `noEmpty` | 零产出补无可补 |
| `n.cardId` 非空 | 卡没了就没有可续的上下文(`WORKER_CARD_GONE` 会清掉它) |
| `n.reason` 不在 `{zero-output, aborted, stalled, card-gone, lost-on-restart}` | 这些都表示"这张卡根本没在干活" |
| `n.kind !== 'verify'` | 验证节点的规程自己写着"验证恒由新分片执行(新眼睛防锚定)"——让同一根棒把自己的报告补圆,等于自己给自己打分 |
| `num(n.patches) < posInt(n.maxPatches, 2)` | 不许无限补。**必须用 num/posInt 兜底**:老存档的节点没有这两个字段,直接比较是 `undefined < undefined = false`,补做分支会静默失效 |

**升级链(先便宜后贵):** 补做(不耗 `attempt`,记 `patches`)→ 补满降级重做(`attempt++`,换新卡)→ 重做用尽 → `failed` + 缺口入账 + 问模型。

**新 effect:** `{ type:'patchNode', nodeId, missing:[{kind,detail}], patch, why }` —— `index.js` 把它渲染成给那张工人卡的一条消息(只说缺什么,不重发整份 brief)。节点回 `running`,重新挂 `silent` 计时。

selftest 用例5(P1~P7)逐条锁死。

### 3.4 四条不变式(`applyEvent` 末尾 assert,`invariants()` 也查)

1. `node.state` / `run.phase` **只在 `applyEvent` 里**被赋值 —— 唯一写者。
2. 同一 `(nodeId, ev.type, seq)` 重复投递必须幂等 —— **不存在「一次性标志」这种东西**。
3. `run.nodes` 只增不删。
4. `applyEvent` 不读时钟/fs/`S`;时间由 `ev.at` 传入。

### 3.5 重启续接

| 落盘时 state | 续接动作 |
|---|---|
| `verified` | 重跑 `evalExit` 复核;过 → 保持;不过 → `pending`(attempt 不增) |
| `settled` | 重跑 `evalExit` |
| `running`/`queued` | 先 `evalExit`:**全过 → 直接 `verified`**(磁盘产出说话);否则 `pending`,`reason='lost-on-restart'`,**attempt 不增**(不惩罚崩溃),消耗 `resumeCredit` |
| `failed`/`skipped`/`cancelled`/`pending` | 原样 |

## 4. `src/orch/nodes.js`

```js
module.exports = {
  makeNode(spec, ctx),                 // 校验 + 补默认 → Node;非法字段抛 Error(调用方转成 invalid)
  validateNodeSpecs(specs, run, ctx),  // → { nodes, errors, truncated }
                                       //   校验:kind 枚举 / deps 可解析 / writeScope 在 dir 内且【两两不交】
                                       //   / nodes.length+spawned<=maxNodes(超出【截断】并置 truncated,不是判不合法)
  evalExit(node, probe),               // → { pass, report:[{kind,ok,detail}], contractMiss, unverified, verdict, cmdExit }
  hasVerifyEvidence(actions),          // 判据从 window.js:642-652 原样搬(VERIFY_CMD 正则 + browser 动作轨)
  checkContract(sigs, texts),          // 判据从 window.js:612-640 原样搬
  parseVerdict(final),                 // 从 window.js:703-724 搬:{ verdict, rejectWhy }
  safeVerifyCmd(cmd),                  // 从 window.js:741-743 搬:shell 元字符黑名单 + 白名单正则 + 括号注释剥离
                                       //   ★一行不许删:命令的作者仍然是模型,只是从报告正文换成了 JSON 字段,信任级别一模一样
}
```

`probe` 是注入的 IO:`{ statSync(p), readFileSync(p), readdir(p), exec(cmd, opts) }`。**`nodes.js` 自己不 require fs/child_process。**

`evalExit` 的检查项(按 `node.exit` 逐条,任一不过则 `pass=false`):
- `artifacts` —— 每个路径必须存在且非空;
- `noEmpty` —— `result.final` 非空 或 `result.files` 非空(零产出 = 网关静默/空答耗尽的典型形态,不能叫完成);
- `contract` —— 签名在写归属文件里找得到(`checkContract`);
- `requireEvidence` —— `hasVerifyEvidence(actions)`;
- `requireVerdict` —— `parseVerdict(final)` 有 VERDICT 字面量,且 PASS 必须带 `Command run` 块;
- `verifyCmd` —— `safeVerifyCmd` 过滤后真跑,**退出码即判据**(拿不到安全命令 → 该项跳过并在 report 里标 skipped)。

## 6. `src/orch/schema.js`

```js
module.exports = {
  extractJson(text),        // ★平衡括号扫描(不是贪婪 /\{[\s\S]*\}/):剥 markdown 围栏、找第一个能闭合的对象
  coerce(point, obj),       // 宽进:单对象包成数组 / 'true' → true / '3' → 3 / null → []
  validate(point, obj),     // 严出 → { ok, errors:[中文] }
}
```

**没有「JSON schema 强约束」这回事** —— 全仓 grep `response_format|json_schema` 零命中,`sendMessage` 的 body
只有 `{parts, agent?, model?, providerID?, modelID?}`。所以底座是:窄提示词 + `extractJson` + `coerce` 宽进 +
手写 validator 严出 + 同会话一次窄重问 + 四级降级梯。

`plan` 输出:`{ needGrounding, nodes[], more:'no'|'unknown', open[], why }`
`replan` 输出:`{ needGrounding, addNodes[], dropNodes[{id,why}], done, askUser, facts[], open[], more, why, final }`

**`done:true` 的硬校验**:`final.gaps` 必须**逐条覆盖**输入里出现的所有 `ledger.gaps` 与「无验证证据节点」清单;
漏了直接判不合法并驳回重问。这是「代码保证信息不丢、模型保留动作权」的落点 ——
取代旧的「代码替它自动补派一根验证棒」那种越权。

## 7. `src/orch/render.js`

```js
module.exports = {
  renderPlan(run, facts),          // facts = index.js 算好的目录事实 {n, bytes, tops[], tree, readmeHead}
  renderReplan(run, ev),
  composeNodeBrief(run, node),     // 总目标 + 本任务 + 上游 facts + 写归属 + 契约 + 产出路径 + 回报格式
  projectSnapshot(run),            // 渲染端只读投影
}
```

**渲染与提示词同文件**是刻意的:渲染成什么、问什么,必须一起改。现状 `window.js:822` 的唤醒文案与规程 `:554`
已经漂成两本账(主控按方案的 M 记账,壳层分母却含校验棒/索引棒/自动补派的验证棒)。

`renderPlan` 里 **N/总字节/顶层分布全部由代码算好后喂进去** —— 旧规程里那 181 字纯算术演算(`M = max(⌈N/20⌉, ⌈总量/150KB⌉)`
加反例)整块从提示词消失。模型只回答「怎么拆」,不回答「几个文件」。

`renderReplan` 必须包含(缺一不可,这是「不许模型说没看见」的机制):
