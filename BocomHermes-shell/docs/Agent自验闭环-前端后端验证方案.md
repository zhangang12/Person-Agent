# Agent 自验闭环方案 —— 改完必须"真的看过能跑"，不准嘴上说完成

> **日期**：2026-07-27。**问题定义**（用户原话）："Agent 太蠢，完成任务后不会自测，特别是前端、后端的验证测试。"
> **定位**：这是 harness 层的"验证闭环"设计，不是壳层自身回归测试（那是另一回事）。与既有机制的关系：`<如实汇报>` 提示词（管态度，第一波）+ 验证证据闸/自动验证棒（管机判兜底，99143a6，已上线）——本方案把验证从"有没有跑构建命令"扩展到**前端真的看过页面、后端真的调通接口**。

## 0. 现状盘点（别重复造）

| 已有 | 覆盖 | 缺口 |
|---|---|---|
| 验证证据闸（shardSettled 机判 bash 流水有无构建/测试命令） | 编码分片、有测试命令的项目 | **普通卡没闸**；只认构建/测试命令 |
| 自动验证棒（全片齐后自动补派"集成验证"分片） | 跑构建/测试，失败按归属回派 | **没有"浏览器自验"这一步**；前端"能 build"≠"页面能跑" |
| `<如实汇报>` 提示词（没验证就明说） | 态度层 | 弱模型该瞎编还是瞎编，要机判兜底 |
| 内嵌浏览器 + CDP（console/网络面板/元素拾取/截图） + repro-mcp（回放/`repro_assert` 断言 `no_console`/`has_element`/`no_net`/V8 覆盖率） + httpcap-mcp（抓包） | 工具面齐全 | **没有编排成"验证剧本"**，Agent 自己想不到用 |
| 弱模型病灶：内网老项目（Java/XML/无测试框架）没测试可跑 | — | "跑 npm test"根本不适用，真实验证=起服务+调接口 |

## 1. 三个闭环

### ① 前端自验闭环（改完前端必须"看一眼页面"）

**触发**：编码任务（分片或普通卡）的改动文件命中前端特征（`*.vue/*.tsx/*.css/*.html` 或落在前端目录约定）→ 验证流程里**必须**包含浏览器步骤，仅有 `npm run build` 不算验过。

**剧本（验证棒/Agent 按此执行，写成傻瓜步骤）**：
1. 起前端（按项目验证档案里的 devCmd；没有则静态打开构建产物目录）。
2. 内嵌浏览器打开入口 URL（档案里的 devUrl）。
3. 断言三连（repro-mcp 现成能力）：**console 零报错**（`no_console`）、**关键元素存在**（`has_element`，档案里登记每页面的关键选择器）、无失败网络请求（`no_net`，可选）。
4. 截图落成果抽屉（用户看得见"真的跑过了"，也是回灌证据）。
5. 失败 → 报错+截图+本次 diff 回灌 Agent 自修，直到断言过或达验证棒上限转人工。

**机判扩展**：证据闸的 VERIFY_CMD 判定里加"browser 动作轨"（page_open/screenshot/repro_assert 任一）——前端任务没有浏览器动作 = 未验证，与"没跑构建"同罪。

### ② 后端自验闭环（改完后端必须"调一下接口"）

- **有测试框架的项目**：跑测试（现有证据闸已覆盖 VERIFY_CMD 机判，不动）。
- **无测试框架（内网常态）**：剧本 = 按档案起服务（startCmd）→ curl/HTTP 调档案登记的关键接口（apiProbes：路径+期望状态码/关键字段）→ **httpcap 抓包留证据** → 失败回灌。
- 弱模型没有档案就不会起服务——**项目验证档案是这个闭环的钥匙**（见 §2）。

### ③ 普通卡"完成"机判（现在只有分片有闸）

- 普通卡回合结束时轻量机判：本轮声称完成且有写类工具调用（edit/write/bash 改文件），但**没有任何验证动作**（构建/测试命令、browser 动作、接口调用）→ 轮末注入一条提醒：
  "你说完成了，但还没有验证过。跑一下验证（构建/测试/打开页面/调接口任选），或者明确告诉我为什么没法验证——读过不等于验过。"
- 不拦截、先提醒（CC verification agent 的 "reading is not verification. Run it." 思想）；wf 卡沿用证据闸硬判。观察两周后决定要不要升级硬闸。

## 2. 项目验证档案（settings，一次配置全局复用）

弱模型不可能每次自己探索"怎么起服务、怎么算验过"——把验证方式资产化：

```jsonc
// settings.json 按项目目录挂（跟知识库同键）
verifyProfile: {
  "<项目目录>": {
    "buildCmd": "npm run build",          // 构建（可空）
    "testCmd": "npm test",                // 测试（可空）
    "devCmd": "npm run dev",              // 前端起服务（可空）
    "devUrl": "http://127.0.0.1:8080",    // 前端入口（可空）
    "smokeSelectors": ["#app .layout"],   // 关键元素断言（可空）
    "startCmd": "./mvnw spring-boot:run", // 后端起服务（可空）
    "apiProbes": [{ "path": "/api/health", "expect": 200, "mustContain": "ok" }]  // 接口探针（可空）
  }
}
```

- 设置页加一个小表单（或在项目背景注入时提示"该项目未登记验证档案"）；验证棒/证据闸/普通卡机判都读它。
- **档案缺失时的兜底**：验证棒先花一步"探索验证方式"（找 package.json scripts/pom.xml/启动类），把结论写回档案再验——一次探索、永久复用（这正是知识库该干的事）。

## 3. 提示词层配套（下波提示词，观测期 08-09 后）

- 委派纪律补"完成"定义："**完成 = 有验证证据**（跑过构建/测试、浏览器里看过、接口调通过其一），不是'代码改完了'。没法验证就明说'没验证'。"
- CC verification agent 两句改写："你的任务不是确认它能跑，是**试图搞挂它**；读过代码不算验证，跑一遍才算。"（`external/claude-code-提示词工程借鉴.md` §4.2，留原文出处）

## 4. 落地顺序与验证

| 步 | 内容 | 验证 |
|---|---|---|
| S1 | 验证档案 schema + 设置页表单 + 档案缺失时的"探索验证方式并回写" | session:test 补例（档案读写/兜底探索触发） |
| S2 | 证据闸扩展：browser 动作轨 + 普通卡轻量机判（提醒版） | replay 用例⑤（普通卡无证据→提醒；有证据→不提醒） |
| S3 | 前端自验剧本进验证棒（断言三连+截图+回灌） | 内网真实项目跑一遍：改个前端文件 → 看验证棒是否截图+断言 |
| S4 | 后端无框架剧本（起服务+apiProbes+httpcap 留证） | 同上，后端项目一遍 |
| S5 | 提示词"完成=有验证证据"（下波提示词，观测期后） | 台账登记 |

**前置依赖**：repro-mcp/browser-mcp 在目标项目可用（MCP 已注册）；前端项目的 devCmd 能起（内网依赖已装——这是硬前提，档案里允许只配 apiProbes 不配前端）。

**与 Loop 工程的关系（一句话说清）**：模型↔工具的主循环在 serve 进程里，壳层改不了（那是 fork 的事，W4.4）；本方案全部在壳层 harness 层——机判、编排、档案、剧本，都是壳层能做到的。
