| `pending`/`queued` | `DECIDED(replan,{dropNodes})` | `skipped` | ★**只有未 running 的能被砍** —— replan 有撤回权是反死板的另一半 |
| 任意 | `USER_ABORT` / `RUN_CANCEL` | `cancelled` | `cancelNode` |
| 终态 | 重复事件 | 不变 | 幂等吸收 —— **这是 B2 结构上不可复现的根据** |

### 2.3 重启续接（`RESUME`）

`journal` 每次 transition 原子写。启动扫 `<userData>/orch-runs/*.json`，非终态 run → `suspended`，用户点【续跑】后逐节点：

| 落盘时 state | 续接动作 |
|---|---|
| `verified` | 先跑一次 `evalExit`（磁盘复核）。过 → 保持 `verified`；不过 → `pending`（`attempt` 不增） |
| `failed` / `skipped` / `cancelled` | 原样保留 |
| `settled` | 重跑 `evalExit` |
| `running` / `queued` | 先跑 `evalExit`：**全过 → 直接 `verified`**（磁盘产出说话，取代规程第 9 条那 80 字纯记账）；否则 → `pending`，`reason='lost-on-restart'`，**`attempt` 不增**（不惩罚崩溃），消耗 `budget.resumeCredit`（上限 1，防重启循环烧预算）。`brief` 由代码追加「**已存在产出：<node.result.files 路径清单>，续做别重来**」 |
| `pending` | 原样 |

`node.sid` 落盘保留。**v1 不尝试 sid 重挂**（`card-init` 的 reattach 分支 `session.js:1160-1175` 存在，但内网 serve 会话是否还活着不可靠）—— 明确列为 v2 增强项，不写进本轮承诺。

### 3.0 决策器的结构性设计（一次解掉 R2 / A3 / A4 / G4）

```js
// src/orch/decide.js —— 真实现。测试注入 fakeDecide。
async function decide(point, ctx, { oc, S, log, model }) {
  const prompt = render[point](ctx)                             // 纯函数
  const serve  = await oc.ensureServe(ctx.dir, S.handlers, log)
  const sid    = await oc.createSession(serve, '编排决策·' + point, ctx.dir,
                                        S.settings.orchDecideAgent || undefined)
  // ★★ 【故意不写 S.sessionInfo】——
  //    session.js:427-436 onPermission 对 !si 的会话【一律 reject】,且 AUTO_ALLOW 排在其后。
  //    于是这段会话【调任何需要审批的工具都会被拒】,包括 run_workflow / run_orchestration。
  //    R2 抱怨的"决策器没有工具"在这里正好是我们要的【结构性工具防火墙】(解 A3,零新代码)。
  //    真正的 grounding 走 probe 节点(见 3.2 needGrounding),不走这里。
  try {
    let raw = await Promise.race([
      oc.sendMessage(serve, sid, prompt, model),                // ★传 model:同一个大脑(解 A2,照抄 dbgTriage:1394)
      new Promise((_, r) => setTimeout(() => r(new Error('timeout')), TIMEOUT[point])),
    ])
    let obj = schema.coerce(point, schema.extractJson(raw))
    let v   = schema.validate(point, obj)
    if (!v.ok) {                                                // 【同会话内窄重问】—— 上下文还在,最便宜的纠错通道
      raw = await Promise.race([                                //  (拿到 B 的"MCP 当场驳回"收益,不需要 MCP 那条腿)
        oc.sendMessage(serve, sid, '你上次输出不合法:' + v.errors.join(';') + '。只输出 JSON,不要解释。', model),
        new Promise((_, r) => setTimeout(() => r(new Error('timeout')), TIMEOUT[point])),
      ])
      obj = schema.coerce(point, schema.extractJson(raw)); v = schema.validate(point, obj)
    }
    return v.ok ? { ok:true, data:obj, raw } : { ok:false, invalid:'schemaFail', errors:v.errors, raw }
  } catch (e) {
    try { oc.abort(serve, sid) } catch {}                       // 超时必 abort,不留在飞请求(A1)
    return { ok:false, invalid:'timeout' }
  } finally {
    try { await oc.deleteSession(serve, sid) } catch {}         // 会话即用即删(解 A4)
  }
}
```

**降级梯四级（采纳 C §5.2，每级都在 `Decision` 里留痕并在面板标红）**：
1. `coerce` 修（剥围栏 / 对象包数组 / 字符串 bool）；
2. 同会话窄重问 1 次；
3. **确定性兜底**：`{addNodes:[], dropNodes:[], done:false}` —— 即"不改图，继续跑"。**这是绝对安全的默认**：不凭空造节点，也不卡住，`budget.invalidStreak++`；
4. `invalidStreak >= 3` → `awaiting-user`。

## 7. 反死板自检

### 7.1 模型的判断权具体在哪

| 代码判断（全是算术 / 文件事实 / 预算） | 模型判断（全是语义） |
|---|---|
| 候选文件 N、总字节、顶层分布 | 哪些路径与目标相关、怎么分组 |
| deps 满足没有、有没有并发容量、过没过铺开闸 | 要不要加节点、加几个、加什么 |
| `writeScope` 两两交不交、在不在仓内 | `writeScope` 该划到哪 |
| 契约签名在不在归属文件里 | 契约该写哪些签名 |
| 跑没跑过构建/测试、`verifyCmd` 退出码 | **要不要验证**（`requireEvidence` 是模型的字段）、PASS/FAIL 语义、截图看着对不对 |
| `attempt`/`spentDecides`/`wave` 超没超预算 | 失败该重试、拆更小、还是放弃 |
| `artifacts` 文件在不在 | **算不算完、要不要收口**（`done` / `more`） |
| 差异检测（声明 vs 实际） | 这个差异要不要紧 |

**没有任何一个"升格与否 / 怎么拆 / 拆几片 / 要不要验证 / 要不要收口"落在左列。**

### 7.2 小批 replan 怎么保证真的发生（四条机制，不是承诺）

1. **每个节点进 `verified`/`failed` 都触发 replan**（§2.1 表第 9 行），是**强制转移**不是"主控想起来才做"。现状的病恰恰是主控只在收到注入时被动醒一次。
2. **★"未经证据不得铺开"闸**（这条三家都没有，是"反死板评审"提的、我采纳并写进状态机）：
   > 在 `run.dispatchedAny === false`（即还没有任何一个节点收官并触发过 replan）之前，同一 run 最多只允许 **1 个无 deps 的节点处于 running**。第二个无依赖节点的派发，必须发生在第一次 replan 之后。
   
   ① **不限制模型的判断权**，一个字都不改它的输出（模型完全可以一口气给出 8 个正确的独立片）；② 让 `wave ≥ 2` 成为**结构保证**而不是桩造的绿 —— `22-run-replan-grows` 的断言从此证的是机制不是 `fakeDecide`；③ 对"单节点就能干完"的目标**零成本**（就一个节点，跑完即收口，没有 survey 没有 verifying 没有 reducing）。
3. **replan 有撤回权**：`dropNodes` 能砍掉还没开跑的 pending/queued 节点，`droppedReason` 留痕。现状完全没有这个能力（派出去就收不回）。
4. **noop 是合法输出** + **`more:'unknown'` 是一等公民**。不强迫模型每次都改点什么（强迫改动是另一种死板）；"我还不知道后面有什么"有地方可写，于是小批成为模型的**便宜选项**而不是代码的强制上限。

### 7.3 "目标形状很怪"（不是探索型、不是编码型）时流程怎么走

**机制级的三条**：

1. **phase 里没有业务阶段**。`executing` 是个大池子，顺序只由模型给的 `deps` 决定。一个 run 完全可以是 `work → done`（无 probe 无 verify 无 reduce），也可以是 `probe → work → probe → work → reduce`。**不存在 survey→work→verify→index 的强制序列。**
2. **代码从不造节点**。`verify`/`reduce`/`probe` 全部来自模型的 `addNodes`。没有 `origin:'auto-verify'` 这个值。
   - 纯分析/整理的 run：模型给的节点 `requireEvidence:false` → `exit` 不查证据 → 不会硬塞验证棒。
   - 单片任务：`facts` 少、模型直接 `done:true` → 不产 README。**这两条都是模型判断的结果，不是代码的 `facts.length<=1` 阈值**（明确否决 B 的两条计数阈值 —— 关键词换成计数，性质一模一样，正是被砍掉的固定 7 角色那版的同一种错误）。
3. **`node.goal` 不截断**。"你是对抗性评审，按以下五条逐条挑刺"这种**现编角色**写得进去。全仓没有角色枚举，`node.kind` 只有 5 个且全是**执行语义**（work/probe/verify/check/reduce），不是职能语义（架构师/评审员）。

**一个真实场景（现状做不到，新设计做得到）**：
> plan 出 2 个节点（铺开闸只放 1 个跑）。n1 跑完发现 chart 依赖一个已停维护的第三方库。
> **现状**：主控收到 `<主控进度>分片「…」已完成 (1/3)…对照你的 todo 清单` 一条中文注入，得在 6.5k 规程 + 自己维护的台账里重新想起来这件事，而且它**无法撤销已经派出去的第 2、3 片**（去重闸只拦 running/排队，撤是撤不了的）。
> **新设计**：replan 输入里明写「刚收官 n1，落盘 docs/list.md，报告尾 1500 字（含第三方库警告）」+ 差异检测。模型返回 `{addNodes:[{kind:'probe',title:'确认 chart 依赖的替代方案'}], dropNodes:[{id:'n3',why:'依赖未决'}], more:'unknown'}`。代码把 n3 转 `skipped`、派出 probe、`wave++`。probe 收官后再 replan，按真实发现重新拆 chart。

### 7.4 反死板的验收判据（比任何文档承诺都管用）

上线后统计真实 run 的 `wave` 分布与 `dropNodes` 命中率。**如果 90% 的 run 全是 `wave=1` 且 `dropNodes` 从未命中，那不管代码写得多漂亮，做出来的就是流水线。** 这条指标必须进 RunPanel，不能只进日志。
